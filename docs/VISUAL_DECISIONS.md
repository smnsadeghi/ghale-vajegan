## ۱. ارزیابی مقایسه‌ای ابعاد صحنه نبرد (Scene Dimensions Evaluation)

یکی از اساسی‌ترین تصمیمات فنی در بازطراحی بصری، انتخاب میان **ابعاد موجود ($480 \times 312$)** و **ابعاد پیشنهادی سینماتیک عریض ۱۶:۹ ($480 \times 270$)** است:

| معیار ارزیابی | ابعاد موجود ($480 \times 312$ پیکسل) | ابعاد پیشنهادی ($480 \times 270$ پیکسل - 16:9) |
| :--- | :--- | :--- |
| **نسبت تصویر (Aspect Ratio)** | تقریباً ۱.۵۴ به ۱ (نامتعارف در گرافیک بازی‌ها) | **دقیقاً ۱۶ به ۹ (استاندارد جهانی صنعت بازی و سینما)** |
| **تطابق با کانسپت‌آرت‌های تولیدی** | تصاویر کانسپت تولیدشده هوش مصنوعی (۱۰۲۴×۵۷۱) دارای نسبت دقیق ۱۶:۹ هستند. استفاده از ۳۱۲px نیازمند کراپ افقی یا اضافه کردن کادر مصنوعی در بالا/پایین است. | **۱۰۰٪ تطابق کامل بدون هیچ‌گونه برش (Crop)، اعوجاج یا کشیدگی در تکسچرها.** |
| **ارتفاع مفید در موبایل‌های عمودی** | ۳۱۲ پیکسل فضای زیادی از صفحه گوشی را اشغال کرده و پنجره سوالات و گزینه‌ها در گوشی‌های با ارتفاع کمتر را به سمت پایین می‌راند (نیاز به اسکرول). | **۲۷۰ پیکسل، ۴۲ پیکسل فضای تنفس عمودی آزاد می‌کند؛** در نتیجه سوال، ۴ گزینه و دکمه‌ها بدون نیاز به اسکرول روی صفحه فیکس می‌شوند. |
| **پایداری گیم‌پلی و لاجیک بازی** | دست‌نخورده باقی می‌ماند. | **کاملاً دست‌نخورده باقی می‌ماند.** محاسبات حرکت شوالیه منحصراً روی محور افقی ($X$) انجام می‌شود و کاهش ارتفاع صحنه هیچ تاثیری در پیشروی کاراکتر ندارد. |
| **حس زیبایی‌شناختی سینماتیک** | عمودی‌تر و شبیه پنجره‌های وب سنتی. | **افقی، فراگیر و دارای قاب سینمایی اصیل بازی‌های سبک Eastward.** |

### تصمیم نهایی و توصیه اجرایی:
> **تصمیم قطعی:** ارتقا به کادر سینماتیک **$480 \times 270$ پیکسل (16:9)** قویاً پیشنهاد و تایید می‌شود. این تغییر بدون ایجاد هیچ ریسکی برای لاجیک بازی، هماهنگی پیکسلی کامل با دارایی‌های تولیدی ۱۰۲۴×۵۷۱ ایجاد می‌کند و فضای عمودی بهتری در موبایل به گزینه‌های کوییز اختصاص می‌دهد.

## ۲. ماتریس تفکیک فرمت دارایی‌ها (Asset Format Strategy)

برای تضمین حداکثر کیفیت بصری و سرعت فوق‌العاده در شرایط اینترنت محدود، فرمت‌ها بر اساس ماهیت فنی کارکردشان تخصیص داده شده‌اند:

```
+----------------------------------------------------------------------------------+
|                    ماتریس تخصیص فرمت دارایی‌های قلعه واژگان                      |
+----------------------------------------------------------------------------------+
|  ۱. فرمت WebP (فشرده‌سازی مدرن Lossless/High-Quality):                            |
|     - کاربرد: پس‌زمینه‌های یکپارچه محیطی (تصویر ۴ و تصویر ۵).                      |
|     - مزیت: حجم زیر ۵۰ کیلوبایت با حفظ وضوح کامل خوشه‌های پیکسلی در دسکتاپ و رتینا. |
|                                                                                  |
|  ۲. فرمت PNG شفاف (32-bit Transparent PNG):                                      |
|     - کاربرد: اسپرایت‌های حرکتی شوالیه، شاهزاده، ۳ هیولای جاده و پراپ‌های سنگی/چوبی. |
|     - مزیت: لبه‌های برشی کاملاً پیکسلی و شارپ بدون خطای بلیدینگ روی هر پس‌زمینه‌ای.   |
|                                                                                  |
|  ۳. فرمت برداری SVG (درون‌خطی با crispEdges):                                     |
|     - کاربرد: شمع‌های مومی HUD، قفل‌های مرحله، آیکون‌های رابط کاربری، خطوط کتیبه‌ها. |
|     - مزیت: صفر بایت لود خارجی، مقیاس‌پذیری نامحدود و کنترل آنی وضعیت با CSS.     |
|                                                                                  |
|  ۴. افکت‌های CSS و DOM:                                                          |
|     - کاربرد: پرتوهای نوری دروازه، اسکن‌لاین CRT، مه شناور جاده، فلیپ سه‌بعدی کارت.  |
|     - مزیت: پردازش توسط GPU بدون اشغال حافظه گرافیکی و عدم نیاز به فریم‌های سنگین. |
+----------------------------------------------------------------------------------+
```

## ۳. سیاست سنجش حجم و عملکرد (No Arbitrary Limits)

به جای اعمال محدودیت‌های مصنوعی و سفت‌وسخت بر حجم فایل‌ها که ممکن است به فشرده‌سازی مخرب و افت کیفیت پیکسل‌آرت منجر شود:
1. **تست کیفیت بصری اولویت دارد:** هر تصویر باید ابتدا در نسبت پیکسلی ۱:۱ مشاهده شود تا از عدم وجود مصنوعات فشرده‌سازی (Artifacts) اطمینان حاصل شود.
2. **سقف استاندارد بودجه دارایی‌های جهان ۱:** 
   - پس‌زمینه کامل WebP نبرد: بین ۴۰ تا ۷۰ کیلوبایت (کیفیت ۹۰٪ WebP).
   - کل شیت اسپرایت‌ها و پراپ‌های استخراج‌شده: بین ۱۰۰ تا ۲۰۰ کیلوبایت.
   - مجموع کل دارایی‌های مرحله نبرد کمتر از ۳۰۰ کیلوبایت خواهد بود که حتی در بستر اینترنت 2G/3G در کسری از ثانیه لود می‌شود.

## ۴. سازگاری با معماری برنامه (PWA & Service Worker)

- تمام دارایی‌های استخراج‌شده در پوشه `staging/` پس از تایید کیفی نهایی، مستقیماً به دایرکتوری پایدار `assets/` در پروژه منتقل خواهند شد.
- هیچ‌کدام از فایل‌های عملیاتی (`index.html` و `sw.js`) در این مرحله تغییر نکرده‌اند.
- در فاز ادغام اجرایی، دارایی‌های جدید در آرایه `ASSETS` در `sw.js` ثبت شده و کش سرویس ورکر به نسخه جدید ارتقا خواهد یافت تا تجربه آفلاین PWA بدون کمترین خللی حفظ شود.
